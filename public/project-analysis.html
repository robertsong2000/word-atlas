The verdict

完整产品的雏形，已经落地。

它已经跨过“演示页面”的阶段。最值得继续投入的，是可靠性与内容质量。

综合评估 / 基于当前仓库

核心功能完成度高，
适合个人使用与静态部署。

无需账号，打开即学。内容、复习调度、练习、统计与备份已形成闭环；但缓存升级、异常恢复和关键流程测试仍需补强，不能视为经过充分验证的商业服务。

可用核心闭环已形成

产品主流程 已实现

今日计划、词汇图鉴、学习、打字练习、个人设置，以及首次引导和词条弹层。

内容与媒体 资源齐全

所有词条具备插画、英美发音及首句朗读；每词两条例句，1,011 个词另有第二句朗读。

工程交付 构建可用

TypeScript 严格模式、单元测试、数据校验与静态打包均已具备，部署不依赖业务后端。

稳定性保障 需要加固

存在离线缓存更新与恢复边界风险；当前测试没有直接覆盖学习会话编排与完整用户流程。

内容准确性 缺少逐条人工审校

自动校验能检查结构和资源存在性，不能证明释义、例句、分级或插画的语义准确性。

多设备能力 手动迁移

进度存于浏览器，可导出和导入备份；账号系统与云同步未实现，也不属于当前产品定位。

Product & learning

从“看过”，走到“想得起来”。

插画负责建立场景，主动回忆负责检索，FSRS 负责安排再次相遇的时间。

认识

看见词义

插画、释义、音标、两条例句、搭配与易混提示组成完整词卡。

回忆

主动作答

选义、看图补句、听音辨词、拼写四种题型，逐步加强提取。

复习

FSRS 调度

按答题表现更新记忆状态，默认目标记忆率 90%，优先复习到期词。

反馈

点亮星图

把词的学习状态映射成星光；每日统计和分享卡让进步可见。

默认每天 10 个新词，每 5 个一组先认识、再打乱回忆。每轮最多安排 120 个到期复习词；错词最多追加两次重试，只有首次作答更新记忆和正确率。

练习与记忆解耦

单词输入、例句抄写、整句听写单独统计 WPM 和准确率，不修改 FSRS 记忆状态，避免抄写被误当成掌握。

“掌握”有具体定义

卡片处于 Review 状态，且稳定度至少 21 天。这是应用内部的进度阈值，不能直接代表雅思能力或提分效果。

0 个结构错误

词条、媒体路径和分块顺序通过；另有 24 条“例句未匹配词头词干”的启发式警告，需要人工核查，不能直接判为错误。

npm run check:atlas
优先缓存升级可能造成新旧词库混用

源码观察：缓存版本固定为 atlas-v1，索引采用网络优先，词条分块采用缓存优先。更新词条内容或排序而不更新缓存版本时，可能出现新索引与旧分块共存。

建议：把缓存版本和数据版本绑定，或给分块 URL 增加版本标识；同时验证升级后的离线访问。

public/sw.js:2,27,42 / src/atlas/data.ts:39

优先清理缓存的范围可能影响同源其他应用

activate 会删除所有不以当前版本开头的缓存。CacheStorage 按 origin 共享，子路径不提供缓存隔离；同域名其他应用的缓存可能被清除。应只删除词光命名空间下的旧版本。

public/sw.js:7-12

恢复进行中的学习会话校验不够完整

恢复本地 session 时，只检查部分顶层字段，再断言为 ActiveSession；没有完整校验步骤元素、整数索引及相关 ID 列表。损坏的本地数据可能令学习页面访问无效 step。备份导入会移除 session，主要风险在本地恢复路径。

src/store/store.ts:155 / src/pages/Learn.tsx:58,80

数据保存失败提示与多标签并发仍有缺口

已有保存失败状态、“我的”页面警告、250ms 防抖与 storage 同步，能处理常见情况。但写入失败后 dirty 已清除，不会主动保留待重试标记；两个窗口同时学习时，完整快照同步仍可能发生覆盖。

建议把保存失败提升为全局提示并补充重试；多标签先明确限制单活跃学习窗口，再考虑更复杂的冲突合并。

Service Worker 只在生产环境注册，没有安装时预缓存全量资源。只有访问并成功缓存的内容可以离线使用；媒体缓存上限 1,500 个条目，Range 请求跳过缓存，浏览器也可能回收存储。

Next priorities

下一步，先让它更可靠。

以下是建议顺序，不是已完成的修复，也不包含虚构的工期承诺。

先处理

保护更新与学习进度

修正缓存命名空间和升级策略；补全本地 session 校验；保存失败时明确告知并允许恢复。优先消除可能影响学习连续性的风险。

再补齐

为学习闭环留下回归证据

增加首次作答只记一次、重试不抬高正确率、刷新后不重复计分的测试；验证新手引导、学习、暂停恢复、备份恢复与离线升级流程。

持续做

把资源规模转化为内容质量

优先审查 24 条词干匹配警告、高频词和易混词，建立纠错记录。根据真实设备和网络观察加载表现，再决定是否调整媒体与分发策略。

按需扩展

以真实需求决定云能力

账号和云同步会引入认证、隐私、冲突处理与运维成本。当前本地优先的定位成立，不需要为了“看起来完整”提前加入业务后端。
